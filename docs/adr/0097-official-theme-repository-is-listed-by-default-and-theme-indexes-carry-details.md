# The official theme repository is listed by default and theme indexes carry details

> **Status:** Accepted, 2026-11-17 ([#1209](https://github.com/LankfordAI/omp-ui/issues/1209), [#1210](https://github.com/LankfordAI/omp-ui/issues/1210), [#1211](https://github.com/LankfordAI/omp-ui/issues/1211), [#1212](https://github.com/LankfordAI/omp-ui/issues/1212), [#1213](https://github.com/LankfordAI/omp-ui/issues/1213)). Amends [ADR-0096](0096-themes-install-from-github-theme-repositories.md): the official repository is listed by default.

A new user saw twelve curated palettes and had to find and add `LankfordAI/omp-ui-themes` before any theme with a backdrop showed up, and the v1 theme index could describe a theme only by its colours. This record lists the official repository without the user adding it, lets the user turn that off, gives theme indexes details and tags, and sets the standard the official repository holds contributions to.

## Decision

**1. The official repository is implicit.** `lankfordai/omp-ui-themes` is listed under Show and accepted by Browse and Install without being added, and uses none of the 16 repository slots. One setting, `officialThemes` (default on), hides it. Nothing is downloaded until the user picks it under Show, and its themes install as ordinary repository themes (ADR-0096), so a theme takes space only once the user chooses it. An install checks that its repository is still listed when the row is written, in the same queue as the switch, so a switch-off queued first wins.

**2. Index v2.** `omp-ui-themes.v2.json` sits beside the v1 index under a new filename, so released builds keep reading v1. New builds read v2 whenever the tree has it and never fall back to v1 when v2 is malformed. v2 ignores unknown root and entry keys and lets an invalid optional field fall to its default, but checks the four required fields exactly as v1 does (one shared helper). It holds up to 500 entries in 512 KiB. v1 stays a generated, capped subset (48 entries, 64 KiB) for 0.36.x; the supported floor is 0.36.1, because 0.36.0 refuses theme files exported without `dim`.

**3. Details.** A theme's tags, description and optional author live in a *theme details file* beside its theme file, never in the theme file, whose released parser rejects unknown keys. Both indexes are generated by a tool, so no PR edits an index. The format accepts any tag of the right shape; the official repository controls its vocabulary in `tags.json`, enforced by its CI, and the Share panel offers a copy of that list (`OFFICIAL_THEME_TAGS`). Details are not persisted on stored themes: `ThemeOrigin` has exact keys and an added key would make older builds drop the row.

**4. The standard.** The official repository's CI runs a tool built from omp-ui (`npm run themes:build-tool`) against every pull request, from the base branch so a PR cannot change its own checker: allowed paths, slugs, pairs of theme and details files, the gate, backdrop limits (1 MiB for images in this repository), the vocabulary, unique labels, no duplicate themes, and generated indexes left untouched. A reviewer checks scope, rights, content and finish. Theme files, details files and their art are CC0-1.0, because attribution cannot travel through Export, Duplicate or Edit and the app has no credits screen; tools and workflows are MIT. `featured.json` names themes that lead both indexes.

**5. Share.** Share on an authored theme collects the details, saves the theme file and the details file with two separate clicks, and opens the contribution guide. It holds no token and builds no upload URL: GitHub's upload page cannot be pre-filled, and its fork behaviour for non-collaborators is unconfirmed.

## Considered options (rejected)

- **Bundling the featured themes inside omp-ui.** Every install would carry art the user may never use. Listing the repository costs nothing until the user browses it.
- **Pre-adding the repository to `themeRepositories`.** Costs a repository slot, and changing the fallback would not reach registries that already store a list.
- **Tags inside the theme file.** The released theme-file parser rejects unknown keys.
- **One hand-edited index.** Conflicts on every pull request.
- **A vocabulary compiled into the app as the only source.** Third-party repositories publish indexes too; the format accepts any valid tag, and only the Share panel's suggestions follow the official list.
- **An attribution licence.** Attribution cannot survive Export, Duplicate or Edit.
- **A popularity sort.** Nothing records how often a theme is installed or used.
- **An agent tool that installs or shares.** Install and Share stay user actions.

## Consequences

- The official repository's themes need the network to browse and install, as any repository's do.
- A copy installed from the official repository stays when *omp-ui themes* is turned off, like any repository theme after its repository is removed.
- Builds before this change see at most the v1 index's 48 themes.
- The Share panel's tag list is a copy of the official `tags.json`; a new tag there needs a release before Share offers it.
- For about a minute after a merge that edits an existing theme, installing that theme fails with the existing "does not match the repository's index" message until the index workflow commits.
