# Routines: opt-in per-host scheduled sessions held to a compiled per-lineage tool policy

> **Status:** Accepted, 2026-11-21 ([#1244](https://github.com/LankfordAI/omp-ui/issues/1244), map [#1246](https://github.com/LankfordAI/omp-ui/issues/1246) covering [#1247](https://github.com/LankfordAI/omp-ui/issues/1247)–[#1258](https://github.com/LankfordAI/omp-ui/issues/1258)). Verified against omp 19.0.1. Amends [ADR-0038](0038-session-scoped-approval-mode-via-config-overlay.md), [ADR-0055](0055-private-sessions-quiet-overlay-plus-bridge-not-config-write.md), [ADR-0061](0061-fleet-dispatch-rides-the-spawn-request.md), [ADR-0067](0067-sidebar-lists-sessions-not-projects.md), and [ADR-0075](0075-webhooks-ride-the-remote-access-listener-with-per-webhook-secrets.md).

omp-ui runs all day with the user's skills, tools, MCP servers, and model configuration, but previously only acted when a user typed a prompt, received an outside webhook POST (ADR-0075), or ran a **Scheduled prompt** inside one long-lived session (ADR-0081). Recurring personal work — a morning overview landed in a reply and vault note, or read-and-draft Gmail/Jira triage that never sends, modifies, or deletes in an outside system — needs fresh background sessions on a wall clock without competing with coding sessions or widening unattended permissions.

omp-ui ships the mechanism and its guardrails, and ships **no built-in routines, no routine templates, and no connectors** (#1246 lock 2, ADR-0091). The feature is named **Routines** (#1250); "Assistant" retires as a working word so it never collides with the transcript's `assistant` role.

## Findings (omp 19.0.1 live probes, #1247, #1248)

- **MCP tool approval keys and tiers (#1247).** Every MCP tool registers under one exact flat name `mcp__<server>_<tool>` (64-char cap with hash suffix past it) and is hard-wired to approval tier `write` regardless of `readOnlyHint`. There are no wildcards and no server-wide keys: one entry covers one tool. Under `write` mode, both read-hinted and mutating MCP tools run silently because `write` mode's floor is `write`.
- **Overlay merge and precedence (#1247).** A per-lineage `--config` overlay carrying `tools.approvalMode` and `tools.approval` entries merges per key (overlay wins same-key; unnamed user/project keys survive). Crucially, an inherited global or project `allow` **outranks** a pinned `always-ask` mode. A tier pin alone therefore leaks any tool the user previously allowed globally.
- **Subagents, `xd://`, `eval`, and `bash` (#1247).** Per-tool `tools.approval` entries are process-wide and reach `task` subagents, `xd://` device writes, and `eval` `tool.<name>()` bridge calls; `tools.approvalMode` does not reach subagents (confirming ADR-0038). `bash` calling a CLI (e.g. `curl`, `gh`, `gcloud`) never consults MCP per-tool entries.
- **Roster removal cannot remove MCP tools (#1247).** MCP tools do not appear in `getEnabledToolNames()` or `getMountedXdevToolNames()`; `setActiveToolPresentation` reports success while both direct and `xd://` calls keep executing. Per-tool `tools.approval` entries are the only hard enforcement layer for MCP tools.
- **Approval frames and unattended waiting (#1247).** An `extension_ui_request` for a prompted tool offers `["Approve", "Approve <subject> for this session", "Deny"]`, parsed by `parseApprovalPrompt`. `Origin: MCP server tool` disappears whenever the tool has an approval entry of its own. "Approve for this session" unlocks that policy key session-wide. An unanswered select holds the turn open forever with no timeout or auto-deny.
- **Start path and cost data (#1248).** `FleetDispatcher.dispatch` (the ADR-0075 webhook route) is the main-native way to start a fresh session with a first prompt; ADR-0091's Refresh-now path is renderer-window-bound. The provider usage window (`LimitsView`) cannot be read before spawning: the bridge runs only inside a live child (5-minute cooldown, no timer), main's copy dies on exit, and `selectReport` collapses multiple accounts of one provider. Conversely, per-lineage `session.warnCost` and `session.maxCost` overlays are live-test-proven (`cost-cap-live.test.ts`), and omp halts all model requests (subagents included) at `maxCost`.

## Trust model

> A Routine run executes unattended on instructions the user wrote, but the *content* it processes — mail bodies, ticket bodies, fetched pages, tool results of any kind — is written by people the user does not control and is attacker-controlled text inside an agent's context. omp-ui sees none of that content: MCP tool results never pass through omp-ui, so no fence like the webhook body's can exist here. What omp-ui provides instead is advice to the model (a standing untrusted-content clause in the run's first prompt), narrowed capability (the compiled per-lineage tool policy of #1252, the outside-sender tool exclusions, and the Private pinning of this ADR), and human gates on everything beyond the allow list (Approval cards that answer Deny unanswered). **The boundary is the tool policy; the notice is advice, not a boundary.** Within the allowed surface — an allowed `bash`, an allowed `web_search`, an allowed URL `read` — an injected prompt can take the run anywhere its user could go, with no egress restriction, no path fence inside the working directory, and no omp-ui component able to tell. A routine's allow list is therefore a grant of the user's own reach, reviewed like one, and CLI-through-`bash` remains not enforced at all (#1252).

## What "never sends, modifies, or deletes on its own" rests on

| Layer | Enforced by | Exact guarantee |
| --- | --- | --- |
| **Per-lineage `tools.approval` entries (`allow` / `prompt` / `deny`)** | **omp** | Honored across main turns, `task` subagents (per-tool `deny` verified; `prompt` gated by Tier L probe L4b), `xd://` device writes, and `eval` `tool.<name>()` calls. Exact key matching (`mcp__<server>_<tool>` or built-in name); no wildcards. |
| **Per-lineage `tools.approvalMode: always-ask`** | **omp** | Floors main-session tools above tier `read` to prompt when no entry exists (e.g. a server that could not be catalogued at spawn). Does **not** reach subagents (ADR-0038). |
| **Per-lineage `session.warnCost` / `session.maxCost`** | **omp** | Warns once at `warnCost` and refuses model requests (subagents included) at `maxCost`, emitting `notice source:"cost-gate"` + `prompt_result error.code:"cost_cap"`. |
| **Private overlay (`omp-ui-private.yml`) + `HINDSIGHT_AUTO_RETAIN=false`** | **omp** | Closes all three passive memory write channels (`autolearn.enabled`, `mnemopi.autoRetain`, `hindsight.autoRetain`) while leaving recall readable (ADR-0055). |
| **Spawn-time total catalog compilation** | **omp-ui** | Compiles `allow` for allow-listed keys, `deny` for explicit Deny rows, and `prompt` for **every other catalogued tool** against the live catalog at fire time, overriding any inherited global/project `allow` on the same key and catching tools added to MCP servers after the routine was saved. |
| **Outside-sender host-tool exclusions (`isOutsideSenderKind`)** | **omp-ui** | Requester kind `"routine"` withholds all nine `omp-ui_fleet_*` tools (including `omp-ui_fleet_project`), `omp-ui_device`, `omp-ui_theme_*`, and `omp-ui_issue_*` at `set_host_tools`; `omp-ui_vault_*` stays mounted under ADR-0048's Home-folder boundary. |
| **Once-only Approval card & mode lock** | **omp-ui** | On any session with `OwnedSessionRecord.routine !== null`, `ApprovalCard` hides `sessionLabel` (Allow once / Deny only) so one approved send cannot unlock unattended sends, and `session:setApprovalMode` refuses. |
| **24 h auto-Deny, configurable wall clock, 60 s settle grace** | **omp-ui** | Unanswered Approval cards receive verbatim `"Deny"` at 24 h (resuming cleanly rather than killing mid-turn); fire-time pinned wall clock (default 30 min, configurable `1..1440` min or `0` = unlimited, #1290) reaps via `settleSession`; finished runs self-Settle 60 s after terminal `agent_end`. |
| **Built-in roster bridge (`omp-ui-routine-guard.ts`) + Private guard** | **omp-ui** (presentation) | Hides deny'd built-ins and memory-write tools (`memory_edit`, `retain`, `learn`, `manage_skill`) from the live roster via `setActiveToolPresentation`. Presentation only — enforcement rests on the overlay. |
| **Authoring authority** | **omp-ui** | Routine update, delete, Run now, and Dry run are restricted to the desktop renderer and authenticated remote web clients; `routines:*` never enters `REMOTE_PROXY_CHANNELS`, and no MCP endpoint tool reads or writes routines. **Amendment:** one host tool — `omp-ui_routines_create` — lets an ordinary session's agent *author* a routine when the user explicitly asked, registered only while `routinesEnabled` is on and never for an outside-sender kind (`isOutsideSenderKind`), so a routine run, webhook, or MCP sender still cannot mint routines. The answerer forces `enabled: false` server-side (the argument schema has no `enabled`, `deny`, or review stamps): every agent-created routine is a paused draft until the user opens the `omp-ui://routine/<id>` review link and flips the enable switch. Arming stays human-only; an agent cannot widen its own policy. **Amendment 2 (#1289):** a second host tool — `omp-ui_routines_update` — lets the same agent *edit* an existing routine (field-level merge over the stored record), and both tools may now carry run hooks (`scripts.pre` / `scripts.post`). Every agent write still lands `enabled: false`: editing a live routine disarms scheduled firing until the user re-arms, and `enabled`, `deny`, `destination.workspace`, and the review stamps remain unexpressible to agents. Run now, Dry run, delete, Test script, and the enable switch stay human-only by absence; an `allow` edit preserves the stored `deny` list verbatim and restamps the review so newly allowed tools prompt at fire. |
| **Standing untrusted-content first-prompt clause** | **Not enforced** (advice only) | Appended after user instructions; tells the model to treat tool output as untrusted data. Model compliance is never a security boundary. |
| **CLIs invoked through allowed `bash` or `eval`** | **Not enforced at all** | `bash` → `curl`/`gh`/`gcloud` never consults MCP per-tool policies. Checking `bash` or `eval` turns the row copper with an explicit disclaimer in the editor and Dry run. |
| **Network egress** | **Not enforced at all** | No proxy pin or socket filter exists. An allowed `web_search`, URL `read`, or `bash` carries unrestricted outbound reach. |
| **Working-directory file reads** | **Not enforced at all** | Tool policy gates tools, not paths. The default `worktree` workspace excludes untracked files (such as `.env`), whereas `checkout` mode exposes the whole registered project directory. |
| **Uncatalogued servers in a subagent** | **Not enforced at all** | If an MCP server was never catalogued (offline at save and fire), its tools lack explicit `prompt` entries; `always-ask` still prompts them in main, but a `task` subagent (`task` is ask-default) would fall back to the user's global policy. |
| **Memory recall cross-scope exposure** | **Not enforced at all** | Private keeps recall readable (ADR-0055). A routine pointed at a work project can recall that project's memories into a context containing attacker text; egress remains governed by the tool policy. |
| **Routine run hooks** | **Not enforced at all** | User- or agent-authored shell (`scripts.pre` / `scripts.post`, #1283, #1289) runs outside every tool-policy layer, as the host user; an agent-authored hook grants no execution privilege an authenticated human client does not already hold, because every hook path sits behind a human click (enable, Run now, or Test). The post hook executes in the run's working directory — a repo script it invokes may itself have been rewritten by the just-finished agent. Env is provider-key-scrubbed; ordinary shell credentials remain reachable by design. |

## Decision

1. **Experimental gate, host-local and off by default (#1246, #1249, #1256).** Registry setting `routinesEnabled` (default `false`), switched as the fourth row on **Settings → Experimental** alongside Artifact library, Lab, and Autoresearch. When off, nothing appears anywhere in the shell, the scheduler fires nothing, retention pauses, `routines:*` channels refuse mutations, and per-run timers park without reaping live runs. **Host Lite** pins `routinesEnabled: false` in `broadcastSettings` and omits all `routines:*` channels from its `ChannelTable` (never stubbed).
2. **Vocabulary and surface (#1249, #1250).** Feature name **Routines**; glossary entries **Routine**, **Routine run** (Owned-session subtype), and **Tool policy**. Managed in a dedicated full-pane **Routines** view opened from a sidebar footer button (carrying a copper badge when a run waits on approval) — not a Settings page (Settings stays twelve pages) and not a sidebar section. Wide viewports render split list + detail; compact (`< 900 px`) drills down with `← All routines`. The header names the serving host (`"{title} on {machine}"`). Both **Run now** and **Dry run** live in the editor header.
3. **Record, storage, schedule, and destination (#1251).**
   - Stored in `routines.json` beside `registry.json` (`RoutineStore`, atomic write, mode `0600`), with per-fire audit rows in sibling `routine-runs.json` (`RoutineRunHistory`, atomic write, `0600`). Dedicated host-local channel pair (`routines:getState` / `routines:state`); nothing routine-related enters `state:changed` except the additive `OwnedSessionRecord.routine: { id, name } | null` marker.
   - Inline instructions capped at 20,000 UTF-16 units; name ≤ 80 code points; 128-bit base64url id.
   - Reuses `PromptSchedule` (`packages/core/src/scheduled-prompt.ts`) extended with `@yearly`, `@monthly`, `@weekly`, `@daily`, `@hourly` expanded to canonical 5-field cron at validation; one schedule per routine; IANA `timeZone` captured from the creating client.
   - **Destination is a registered local Project only** (`{ projectCwd, workspace: "worktree" | "checkout" }`, default `worktree`), mode `"build" | "plan"` (default `"build"`), nullable `model` / `thinkingLevel` (null = project chain; `favoritesFirst` stays `kind === "agent"` only). Every fire starts one **fresh** Routine run via `FleetDispatcher.dispatch` with `FleetRequester.kind: "routine"` and `machineKey: LOCAL_MACHINE_KEY`.
   - Adopts `ScheduledPromptRunner`'s four clock rules verbatim: 60 s `MAX_WAIT_MS` timer cap, advance-before-dispatch (never sent twice), late fire with folded missed count past 120 s (never a burst), and per-routine skip-don't-queue while the last run satisfies `inRun = turns.isRunning(tabId) || awaitingHumanAnswer(tabId)`. **Run now** fires identically without advancing `nextRunAtMs`.
4. **Compiled tool policy and approval contract (#1252).**
   - Explicit allowlist (`allow` checked) + optional hard `deny` toggle; absent keys resolve to `prompt`. Default new-routine allows: `read`, `grep`, `glob`, `find`, `ls`, `write`, `edit`, `web_search`, and the `omp-ui_vault_*` tools. `bash`, `eval`, `task`/`wait`, memory, browser/device/council/`lsp`/`debug` start unchecked (`prompt`).
   - Compiled **at fire time** against the live tool catalog into `omp-ui-approval.yml` (`tools.approvalMode: always-ask` + total per-tool `tools.approval` map) plus a generated built-in roster bridge `omp-ui-routine-guard.ts` for deny'd built-ins. Tools added to a server since `lastReviewedAt` / `reviewedCatalog` compile to `prompt` and show `Added later · not allowed`. **Dry run** executes the exact same compiler without writing or spawning.
   - Routine runs persist their compiled approval entries, spend cap, and denied built-ins on the session record (or lineage-pinned snapshot re-read by `writeSessionOverlays`) so human continuations keep the exact policy for life (#1255).
   - Routine-run `ApprovalCard` offers **Allow once / Deny** only (hiding `sessionLabel`), `session:setApprovalMode` refuses, and an unanswered card auto-answers verbatim `"Deny"` at 24 h. Amendment (#1276): the card also offers **Always allow**, which answers the held frame once and appends the tool key to the stored routine's `toolPolicy.allow` — a human-clicked grant amends the routine *definition* for future fires, never the fire-time snapshot pinned on the session record.
   - **Gating live probe (L4b, #1252/#1257):** if omp 19+'s yolo-resolving `task` subagent executes a `prompt`-marked MCP tool silently instead of blocking/prompting, the compiler must tighten before shipping (either emitting `deny` for non-allowed MCP tools or pinning `task: deny` on routine runs, with this ADR amended).
5. **Coding-first limits (#1253).**
   - **Host-wide active-turn lane:** at most one Routine run with `turns.isRunning === true` per host. A run parked on an Approval card releases the host lane (while keeping its per-routine overlap latch). Busy clock fires skip with a `skipped` notice + `Skipped` history row; busy **Run now** returns an inline refusal and spawns nothing. A **post-run hook** (#1283) holds only the per-routine overlap latch after the run is finalized — it holds no model work, so it never occupies the host-wide lane and other routines' turns stay free while it runs (bounded by its own 60 s cap).
   - **No usage-window pre-check, no model warning, no yielding.** omp's own usage-limit error fails the first prompt cheaply into a `Failed` row.
   - **Spend cap:** registry pair `routineWarnCostUsd` / `routineMaxCostUsd` (defaults `2` / `5`, edited under **Settings → Experimental** while `routinesEnabled` is on; per-routine override; `0` = uncapped) written into a per-lineage `omp-ui-spend.yml` overlay (`session.warnCost` / `session.maxCost`).
   - **Wall clock:** default 30-minute limit from fire (running through parked-card time), reaped via `settleSession` into a timeout `Failed` row. **Amendment (#1290):** configurable per routine via `timeoutMinutes: number | null` (`null` = 30 min default, `0` = unlimited, `1..1440` = custom minutes up to 24 h) and pinned from the scheduler's fire-time record snapshot so mid-run edits or deletes cannot alter a live run. When unlimited, the run holds no wall-clock timer (24 h Approval auto-Deny, 60 s self-Settle, and `maxCostUsd` remain active); an unlimited run that stalls without an Approval card holds the host-wide routine lane until manually stopped or stopped by spend cap.
   - **Warmth:** `isLastActiveInProject` excludes routine-marked records so runs neither win nor steal a coding session's warmth slot. Warm pool already excludes fleet spawns (`req.fleet == null`).
   - **Renderer cost:** tab-less RPC boot/reduce cost was measured (gist `4ae2170a8bc7bc05ed203e73d4340b47`) and accepted — host lane caps concurrent streams at one.
6. **Security boundary (#1254).**
   - Every Routine run stamps `private: true` (ADR-0055 overlay + `HINDSIGHT_AUTO_RETAIN=false` + `/omp-ui-private` guard; recall stays readable).
   - Shared `isOutsideSenderKind(kind)` predicate in `packages/core/src/fleet.ts` unifies `"webhook" | "mcp" | "routine"` across `fleetToolAccess` (`"external-sender"`) and the device/theme/issue host-tool exclusions in `session-manager.ts`.
   - `routinePrompt` appends the standing untrusted-content clause after user instructions.
   - Vault ADR-0048 stays unchanged (no sixth frontmatter key; lineage stamp + record marker link note to routine).
   - Diagnostics redaction manifest explicitly never reads `routines.json` or `routine-runs.json`; run-history rows and notices carry fixed failure strings only — never prompt text, tool arguments, or credentials.
7. **Run lifecycle, visibility, notifications, retention (#1255).**
   - **Title:** `` `${name} · YYYY-MM-DD HH:mm` `` in the routine's IANA zone, fixed digits.
   - **Self-Settle:** 60 s (`ROUTINE_RUN_SETTLE_GRACE_MS`) after terminal `agent_end`, re-checking `inRun` and calling `settleSession(tabId)`. Cancelled by `agent_start` or an open answer gate. Never joins renderer `Mod+Z` undo. All three per-run timers (60 s settle grace, 24 h auto-Deny, pinned wall clock when limited) share one main-process owner and park together when `routinesEnabled` turns off. Amendment (#1283): when a **post-run hook** is configured, it runs between finalization and arming the grace — so a hung hook's delay is capped by the hook's own 60 s budget, not added on top of a live grace window.
   - **Sidebar & Attention:** Routine runs are excluded from all coding sidebar sections (Pinned, Main, Working, Snoozed, Settled) and the footer live count. `buildAttentionEntries` carves out settled-unread routine runs as `ready` until opened.
   - **Notifications:** `DesktopNotifier` adds zero new kinds; existing `turn-complete` fires naturally and closes on self-Settle exit.
   - **Retention:** 30 days (`ROUTINE_RUN_RETENTION_DAYS`) of last activity (`cachedModified ?? launchedAt`) per routine, pruned at boot, post-fire, and gate re-enable via `deleteSession(tabId, false)` for dormant, no-gate runs (unmerged worktree branches survive `kept-unmerged`; replied-to runs are exempt by advancing `cachedModified`; `forkSession` clears `routine: null`). Run-history rows stay marked `pruned` and age out 30 days after fire.
   - **Disable / delete:** gate off suspends without reaping; deleting a routine confirms with live/retained counts, removes record + history without reaping, and clears `routine: null` on surviving session records so no transcript becomes an invisible orphan.
8. **Remote web clients, joined instances, Android, and version skew (#1256).**
   - Authenticated remote web clients and Android get full Routines parity (CRUD, Dry run, Run now, once-only Approval cards) with zero client-kind restrictions; Android has no push notifications (`INTERNET` only).
   - Joined remote instances never see `routines:*` channels (absent from `REMOTE_PROXY_CHANNELS`); runs arrive only as ordinary owned sessions in merged state, and remote card answers ride tab-routed `rpc:send` with identical transcript recording and no per-client attribution.
   - Two hosts never coordinate; the pane header names the host.
   - **Version skew:** no version handshake is required because `routines:*` is never proxied, local-only destinations mean `kind: "routine"` never crosses the wire to an old member's `parseFleetRequester`, and old joiners ignore the additive `routine` summary key. **Reopener note:** any future proposal that targets a remote machine or proxies a routine channel reopens version skew and inherits ADR-0075's member-refusal rules.
9. **Run hooks (#1283, amendment).**
   - **Two optional shell commands per Routine**, stored as strings in the 0600 `routines.json` record (`scripts.pre` / `scripts.post`, each ≤ 8 000 UTF-16 units, tab/LF only). User-facing copy says "run hook"; internal identifiers keep the `scripts` / `postScript` contract naming.
   - **Pre runs in the destination checkout** inside `dispatchRoutine()` — before catalog compilation, so the worktree does not exist yet and a pre hook can never seed it. It **fails closed**: nonzero exit or 60 s timeout refuses the fire (`failed` row, reason `pre-script`); exit code 78 (`EX_CONFIG`) means "nothing to do" (`skipped` row, reason `pre-script-skip`, no failure framing). A hook that finishes after gate-off or deletion dispatches nothing — "gate off fires nothing" outranks an in-flight hook.
   - **Post is a bounded once-per-run finalizer** in the run's actual working directory (pinned at bind time, never re-read), started between outcome finalization and the settle-grace arm by whichever path finalizes first (terminal end / wall-clock reap / exit). It **never rewrites the run outcome**; it records only the fixed `postScript` column (`ok` | `failed` | `timeout` | `interrupted`) and holds the per-routine overlap latch until it finishes or times out. A wall-clock reap resolving false records `interrupted` and runs nothing — no shell beside an un-reaped agent.
   - **Environment:** provider keys are removed with the same core helper non-omp children get (`withoutProviderKeys` ∘ `withoutAppImageRuntime`), inherited `OMP_UI_ROUTINE_*` keys are swept, and only a fixed variable set is injected (`OMP_UI_ROUTINE_ID` / `_TRIGGER` / `_PROJECT_CWD` / `_WORKSPACE` / `_OUTCOME` / `_REASON_CODE` / `_TAB_ID` / `_RUN_CWD`). Ordinary shell credentials (gh, AWS, SSH agent) remain reachable — intended, and the reason the editor carries the copper warning.
   - **Nothing dynamic persists.** Audit rows and notices carry fixed codes only (#1254); unattended hook output is discarded. Only the attended *Test script* action (`routines:testScript`, host-local like every other `routines:*` channel, never proxied) returns output — capped tails, inline, never stored.
   - **Agent-authorable (#1289, amendment 2 — supersedes "host-authored in intent").** Hooks were absent from `omp-ui_routines_create` and `AGENT_CREATE_KEYS`; both agent tools now carry `scripts`, still capped at ≤ 8 000 UTF-16 units per phase with unsafe control chars rejected. The true execution boundary, stated exactly: scheduled fires are gated by `enabled` and the agent can never arm one; **Run now executes disabled routines today** (`routine-scheduler.ts` `runNow` checks only the global gate) and its dispatch runs the pre hook — existing human-only behavior; **Test script** runs whatever command the user submits from the editor, never an agent-authored value unattended. The accepted authorization position, extending the ADR's existing remote-client argument: hooks only ever execute behind a human click (enable, Run now, or Test) and are plainly visible in the Routines editor's "Run hooks" panel at that moment; an agent-authored hook grants no execution privilege an authenticated human client does not already hold. A per-edit re-approval stamp for hook edits remains deferred deliberately. An edit racing a live fire cannot un-run it: `dispatchRoutine()` proceeds from the captured definition, bounded to at most one occurrence, cannot recur (the timer is parked by the disabled state before the next tick), and holds for human edits today.
   - **Rejected:** repo-checked-in hook files (a `write`/`edit`-allowed injected agent could rewrite the file the next fire executes unattended); per-trigger scripts (the trigger rides `OMP_UI_ROUTINE_TRIGGER`); sandboxing (neither the worktree nor a scrubbed env is one).

## Considered options (rejected)

- **Pi Durable (`@earendil-works/pi-durable`) as the routine runtime (rejected at charting, #1244, #1246 lock 4).** It is a harness-building library, not the omp runtime: carries no skills, `AGENTS.md`, memory, or MCP setup, duplicates ADR-0069's rejected second runtime, produces non-omp runs lacking the native transcript, Approval card, HUD, and Stats, and marks its own API experimental.
- **Built-in routines, templates, or first-party connectors (rejected at charting, #1246 locks 2 & 9, ADR-0091).** omp-ui provides the mechanism; connectors stay omp MCP servers or CLIs.
- **Messaging channels (Telegram/Discord) and Android push notifications (deferred at charting, #1246 lock 8).**
- **Single persistent "desk" assistant or Scheduled prompt on one session (rejected, #1244, #1251, ADR-0059).** Context grows unbounded and cannot be branched/pruned cleanly per fire.
- **Settings page or dedicated sidebar section for Routines; dedicated Routine runs sidebar section or `routine` chip on coding rows; Run-now-only or Schedule-only triggers; 3-state matrix or server-card policy editors (rejected, #1249).** User selected full-pane Routines view, allowlist checklist with optional Deny, attention-only sidebar visibility, and Run now + Dry run.
- **Keeping "Assistant" as feature name; *Firing*/*Execution* for Routine run; standalone Allow list / Fire / Held-run glossary entries; ordinary-session-plus-chip instead of subtype (rejected, #1250).**
- **Chat as a routine destination and persistent `routines/<id>/` scratch root (rejected on informed reversal, #1251).** Four machinery changes (`NewChatSpawnRequest.fleet`, dispatcher chat branch, `fleetToolAccess` exception, ADR-0059 scratch lifecycle) for durable output that already lands in vault notes.
- **Storing routines in `registry.json`, instructions in separate user-edited files, interval/multi-time/6-field/`L`/`#` schedule shapes, remote Project destinations, previous-run transcript pointers, or Run now advancing `nextRunAtMs` (rejected, #1251).**
- **Overlay-only without built-in roster bridge; `deny` for all non-allowed tools; save-frozen entry list; per-server or `readOnlyHint` grain; additive inheritance of user global `tools.approval`; offering session-wide Approve on routine Approval cards; never-expiring or kill-on-expire waiting cards; forbidding `bash`/`eval` outright; custom prompt-excerpt card banners; refusing save on unknown/offline catalog tools (rejected, #1252).**
- **Host lane counting card-parked runs; configurable N or no host lane; queuing busy fires; persisted usage-window snapshot or start-then-stop; static shared-provider model warnings; daily/app-wide dollar ledgers or no spend cap; deferring fires for coding turns; short forced hibernation window; wrap-up-grace or active-time-only wall clock; deferring `bootRpcTab` or gating frame broadcasts (rejected, #1253).**
